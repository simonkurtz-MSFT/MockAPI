Request lifecycle

How MockAPI works

Define the response you need, call its URL, and change it while the application keeps running.

  1. 1

    Define

    Choose methods, an exact path, and the status, headers, content type, and body to return.

  2. 2

    Match

    Each request is matched to an enabled endpoint by method and normalized path. Query strings do not affect matching; unmatched requests return 404.

  3. 3

    Respond and observe

    MockAPI returns the configured response and updates process-local statistics without storing request or response content.

Edits
Valid changes become active atomically, with no restart.
Persistence
Changes are saved automatically to the configured file or Azure Blob Storage. If saving fails, changes stay active but unsaved; select Retry save. Local containers need a persistent volume at /data.
First run
Load the examples, test an endpoint, and edit its response. Changes are saved automatically.
